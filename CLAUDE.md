# TOTPConformanceTests

Conformance suite for the Open Charging Cloud TOTP token format, holding two
implementations to one set of canonical vectors: Hermod's `TOTPGenerator`
(C#, `libs/Hermod`) and TOTP.ts (TypeScript, `libs/TOTP.TS`).

## Orientation

- **The specifications:** `spec/totp-token-format.md` (v1.0, final) — the
  format is FROZEN by deployed verifiers; the spec describes it as
  implemented, quirks included (modulo bias, hash-as-ring-buffer, epoch
  wraparound). Never "improve" the token derivation anywhere.
  `spec/totp-http-authentication.md` (draft) — the HTTP bindings
  (`Authorization: TOTP` scheme, `TOTP` request header), written against
  Hermod's `HTTPTOTPAuthentication`/`TOTPHTTPHeader`; the server-side
  verification in Hermod is still in progress and must follow it.
- **The vectors:** `TestVectors/*.json` are GENERATED by
  `tools/generate-test-vectors.py` — edit the generator, rerun it, never the
  JSON. The generator refuses to write when the hand-cross-validated anchors
  mismatch. `--check` is the CI drift guard and compares byte-for-byte
  (hence `.gitattributes` forces LF on these files). The generator also
  mirrors the files into VENDORED COPIES inside the submodules
  (`libs/Hermod/HermodTests/TOTP/TestVectors/`, `libs/TOTP.TS/test/vectors/`)
  — the implementations' own suites run against those, and
  `VendoredCopiesTests` fails when a copy drifts. After regenerating, commit
  the implementation repos first, then bump the pins here.
- **What implementations get wrong:** `docs/spec-deviations.md`. Each
  deviation is marked on its vector (`knownDeviations`) AND pinned by a
  characterization test in `Tests/TOTPConformance_Tests/KnownDeviationTests.cs`.
  Fixing one in Hermod means: remove the marker in the generator, regenerate,
  delete the characterization test.
- **OCPP 2.1 lineage:** the format was developed for OCPP v2.1; use case C25
  defines it as "TOTP algorithm, version 1" (sha256/Base62 profile).
  `docs/ocpp-totp-comparison.md` maps the OCPP text to spec/implementations
  and lists OCPP modernization proposals. The verbatim OCPP extract in
  `specs/` is CC BY-ND 4.0 (© Open Charge Alliance) — NoDerivatives: never
  reword the quoted OCA text, only extend the clearly-marked annotations.

## Build & test

```
git submodule update --init --recursive
dotnet test TOTPConformanceTests.slnx
npm --prefix Tests/TOTPConformance_Tests.TS install
npm --prefix Tests/TOTPConformance_Tests.TS test
python tools/generate-test-vectors.py --check
```

Expected: C# 92 passed / 1 skipped (length-fractional, not representable in
the UInt32 API), TS 58 passed / 4 skipped (TLS channel binding vectors and
the HTTP-auth vector file — Hermod-only capabilities). Skips are
load-bearing, not noise.

## Ground rules

- **The implementations are not here.** `libs/` holds submodules; changes to
  the TOTP code belong in the Hermod/TOTP.ts repositories. This repository
  holds spec, vectors, and harnesses.
- New vectors: add to the generator with a fresh id (ids are stable, never
  reuse), regenerate, and make sure BOTH harnesses run them (or mark
  `requires`/`notApplicable` deliberately).
- A vector may only enter the file when at least two independent
  implementations agree on it (generator + one harness minimum).
- `libs/Directory.Build.props` shields the submodules from this repo's build
  settings — keep it.
- CI gates the pinned submodules (Windows + bare debian:13 container, Hermod's
  own two legs); `nightly.yml` instead advances the submodules to upstream
  HEADs (`git submodule update --remote`, via `branch = master` in
  .gitmodules) — a red night with green CI means an upstream master broke the
  frozen format, not this repository.
