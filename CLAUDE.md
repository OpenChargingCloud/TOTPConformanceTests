# TOTPConformanceTests

Conformance suite for the Open Charging Cloud TOTP token format, holding two
implementations to one set of canonical vectors: Hermod's `TOTPGenerator`
(C#, `libs/Hermod`) and TOTP.ts (TypeScript, `libs/TOTP.TS`).

## Orientation

- **The specifications live in the `libs/specification` submodule**
  (OpenChargingTechnology/Whitepapers → `TimeBasedOneTimePasswords/`, the
  normative home; this repository holds only harnesses and analysis).
  `totp-token-format.md` (v1.0, final) — the format is FROZEN by deployed
  verifiers; the spec describes it as implemented, quirks included (modulo
  bias, hash-as-ring-buffer, epoch wraparound). Never "improve" the token
  derivation anywhere. `totp-http-authentication.md` (draft) — the HTTP
  bindings (`Authorization: TOTP` scheme, `TOTP` request header), written
  against Hermod's `HTTPTOTPAuthentication`/`TOTPHTTPHeader`; the
  server-side verification in Hermod is still in progress and must follow it.
- **The vectors:** the annex
  `libs/specification/TimeBasedOneTimePasswords/test-vectors/*.json` is
  GENERATED by `TimeBasedOneTimePasswords/tools/generate-test-vectors.py`
  (same submodule) — edit the generator, rerun it, never the JSON. The
  generator refuses to write when the hand-cross-validated anchors mismatch.
  `--check` is the CI drift guard and compares byte-for-byte (Whitepapers'
  `.gitattributes` forces LF on the annex). The `--mirror` flags refresh the
  VENDORED COPIES inside the implementation submodules
  (`libs/Hermod/HermodTests/TOTP/TestVectors/`, `libs/TOTP.TS/test/vectors/`)
  — the implementations' own suites run against those, and
  `VendoredCopiesTests` fails when a copy drifts. After regenerating, commit
  in order: Whitepapers first, then the implementation repos, then bump the
  pins here.
- **What implementations get wrong:** `docs/spec-deviations.md`. Each
  deviation is marked on its vector (`knownDeviations`) AND pinned by a
  characterization test in `Tests/TOTPConformance_Tests/KnownDeviationTests.cs`.
  Fixing one in Hermod means: remove the marker in the generator, regenerate,
  delete the characterization test.
- **OCPP 2.1 lineage:** the format was developed for OCPP v2.1; use case C25
  defines it as "TOTP algorithm, version 1" (sha256/Base62 profile).
  `docs/ocpp-totp-comparison.md` maps the OCPP text to spec/implementations
  and lists OCPP modernization proposals. The verbatim OCPP extract in
  `specs/` is CC BY-ND 4.0 (© Open Charge Alliance) — NoDerivatives: never
  reword the quoted OCA text, only extend the clearly-marked annotations.

## Build & test

```
git submodule update --init --recursive
dotnet test TOTPConformanceTests.slnx
npm --prefix Tests/TOTPConformance_Tests.TS install
npm --prefix Tests/TOTPConformance_Tests.TS test
python libs/specification/TimeBasedOneTimePasswords/tools/generate-test-vectors.py --check
```

Regenerating (after a generator change) additionally refreshes the vendored
copies: append
`--mirror libs/Hermod/HermodTests/TOTP/TestVectors --mirror libs/TOTP.TS/test/vectors`.

Expected: C# 104 passed / 1 skipped (length-fractional, not representable in
the UInt32 API), TS 58 passed / 4 skipped (TLS channel binding vectors and
the HTTP-auth vector file — Hermod-only capabilities). Skips are
load-bearing, not noise.

## Ground rules

- **Neither the implementations nor the specification are here.** `libs/`
  holds submodules; changes to the TOTP code belong in the Hermod/TOTP.ts
  repositories, changes to spec or vectors in
  OpenChargingTechnology/Whitepapers. This repository holds the harnesses,
  the deviation analysis and the OCPP comparison.
- New vectors: add to the generator with a fresh id (ids are stable, never
  reuse), regenerate, and make sure BOTH harnesses run them (or mark
  `requires`/`notApplicable` deliberately).
- A vector may only enter the file when at least two independent
  implementations agree on it (generator + one harness minimum).
- `libs/Directory.Build.props` shields the submodules from this repo's build
  settings — keep it.
- CI gates the pinned submodules (Windows + bare debian:13 container, Hermod's
  own two legs); `nightly.yml` instead advances all four submodules —
  specification included — to upstream HEADs (`git submodule update
  --remote`, via `branch = master` in .gitmodules) — a red night with green
  CI means an upstream master broke the frozen format (or the annex moved
  without follow-up), not this repository.
